## Cloudflare 504 根因与耗时

旧版 `pricing_settings.go` 对每个样本执行一次关联 `SUM(cost_usd)`，随周期内请求数增长重复扫描。初版 v0.15 先按 `cycle_id, requested_at, id` 读一次事件，在 Go 中按样本时间累计前缀和，但仍用一个长事务写回。**下方初版耗时保留作历史记录；最终实现已改为短批次，见文末安全修订。**

| 本地副本计时 | v0.14.0 旧实现 | v0.15.0 新实现 | 约提升 |
|---|---:|---:|---:|
| 完整 111,661 条请求重计价与样本更新 | 13.854 秒 | 1.477 秒 | 9.4 倍 |
| 仅 6,054 个样本累计步骤（同一批已重计价事件） | 5.721 秒 | 0.413 秒 | 13.9 倍 |

旧版完整计时在独立的 `v0.14.0` worktree 运行；新版在相同原始快照的另一副本运行。样本步骤对比使用完全相同的新版请求计价值，以隔离价格公式变化。将新版每个样本与旧关联 SQL 逐条比对：**6,054/6,054** 个样本差值都小于 `1e-8`，最大绝对差 `3.13e-10`（浮点求和顺序）。本地硬件与线上 VPS 不同，不能把 1.477 秒视为线上耗时保证；异步任务让浏览器不再等待完整历史重算。

在线容量对每段使用已保存请求的实际计价值，包含缓存写入及自定义长上下文阈值。为避免近期用量表重复扫描全部历史段，按账号一次计算各周期尺度；同一副本的 30 天 `/usage` 本地耗时由 3.88 秒降到 0.80 秒。

## 长上下文重复计价修正（本地，未部署）

学习器的长上下文参数相对标准 Credits 形状，是绝对倍率。在 API 口径下，旧算法先用官方长价，再乘拟合倍率 1.079，相当于重复加价。修正后，已标定时直接用“计算后的标准单价 × 拟合倍率”；锁定先验时才使用官方长价。Fast 也按替代规则验证，不叠乘官方倍率。价格表的长上下文列改为显示计算倍率、官方输入倍率和已标定区间。

使用原始 `/tmp/cqe-calibration-20260923.sqlite` 的独立副本重建、拟合和全量重计价，当前周期 11 的 API 每 1% 额度计价值为：锚定 5.6 Sol **$17.701 [$15.152, $20.680]**，锚定 Astra **$14.928 [$12.778, $17.439]**。先前的 $19.873 和 $16.757 为重复计价结果，分别高估约 12.3%；上表已替换为修正后的数值。Credits 和 custom 行未重新测量，仍为先前结果。

每日段重建已改为先在只读连接准备每个 key，再逐 key 短事务写入。本地原始快照这轮完整重建 3.47 秒，最长单 key 写事务 **113.1 ms**；另一独立副本为 45.9 ms。总耗时比旧单事务 1.41 秒长，但唯一写连接不再连续占用。每小时只重新拟合选定 lag 的最终权重，滚动回测每 24 小时最多一次；手动标定仍立即回测。

## 部署前安全修订：短批次与用量保护

本节取代上文“单个长事务”的实现描述。任务先在短暂锁内切换内存 `cfg`，让随后进来的请求采用目标价格，再通过独立只读 SQLite 连接计算历史事件快照。历史重计价、学习器归属更新及逐周期样本累计均以约 **500 行/批**的短事务写入；批次之间释放唯一写连接并暂停 2 ms。任务期间接口返回 `recalculating`，历史图可能暂时混用新旧值；结束时对新增事件涉及的周期再补算样本。失败先恢复旧 `cfg`，再按批恢复旧事件值和样本值，新进请求也换算回旧口径。

本地同一 111,661 条请求快照，关闭写连接的自动 WAL 检查点、由独立连接每 30 秒执行 PASSIVE 检查点后，两次完整复测分别得到：

| 本地复测 | 第一次 | 第二次 |
|---|---:|---:|
| 重计价总耗时 | 1.771 秒 | 1.761 秒 |
| 重计价最长单批占用连接 | 5.884 ms | **6.189 ms** |
| 归属更新总耗时 | 1.581 秒 | 1.592 秒 |
| 归属更新最长单批占用连接 | 5.634 ms | **5.559 ms** |

初次尝试保留 SQLite 默认自动检查点时，偶发单批 148 ms，另一轮达 643 ms；这正是改用独立 PASSIVE 检查点的原因。本地最长占用低于 100 ms 目标；VPS 性能可能更慢，故写入遇到 busy／超时会在约 30 秒内重试。同一摄取 ID 去重，避免“已提交但客户端超时”造成重复；最终失败的计数写入 `metadata.dropped_usage_events` 并显示在仪表盘。

并发单测在重算首批提交后暂停任务，期间插入一条用量并检查其按目标口径入账；任务结束后事件总数和所有样本都与直接 SQL 求和一致。失败路径也覆盖了任务期间插入的事件：旧口径恢复后，该事件被重新计价且相关样本补入贡献。慢归属写入钩子验证 `a.mu` 在 I/O 期间可取得读锁。拟合触发的重计价只在当前口径的模型 adj、Fast 或长上下文因子相对变化超过 2% 时启动，并以持久化时间戳限为每六小时最多一次；custom 不因拟合触发。旧设置升级的重计价在插件注册后由后台任务完成。
